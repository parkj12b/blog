# Changes from C99

## Alignment specification

### The Components

- **`_Alignas`**: A specifier used to force a variable or struct member to a specific byte boundary.
- **`_Alignof`**: An operator that returns the alignment requirement of a specific type (similar to `sizeof`).
- **`aligned_alloc`**: A standard library function for dynamically allocating memory on a specific alignment boundary.

### Important Rules to Remember

1. **Powers of Two Only:** Valid alignment requirements are always powers of two (**1, 2, 4, 8, 16, 32, 64**, etc.). You cannot request a 3-byte or 5-byte alignment.
2. **Size Multiples:** When using `aligned_alloc(alignment, size)`, the `size` parameter must be a mathematical multiple of the `alignment` parameter. If you ask for a 64-byte alignment, your size must be 64, 128, 192, etc. If it isn't, the function's behavior is undefined (it will often just return `NULL`).
3. **Standard Freeing:** You do not need a special "aligned free" function in C11. Pointers generated by `aligned_alloc` are perfectly safe to pass into the standard `free()` function.

### Example

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdalign.h> // Provides 'alignas' and 'alignof' macros

// Using alignas on a struct member to force the whole struct's alignment
// 64 bytes is a common size for modern CPU cache lines.
struct CacheLineData {
    alignas(64) int data[4]; 
};

int main(void) {
    // --- 1. alignof operator ---
    // Checks the default or forced alignment of types
    printf("Standard char alignment: %zu byte\n", alignof(char));
    printf("CacheLineData struct alignment: %zu bytes\n", alignof(struct CacheLineData));

    // --- 2. alignas specifier ---
    // Forcing a standard char array (normally 1-byte aligned) 
    // to sit on a 32-byte boundary in memory.
    alignas(32) char buffer[128];
    printf("Custom local buffer alignment: %zu bytes\n", alignof(buffer));

    // --- 3. aligned_alloc function ---
    // Usage: aligned_alloc(alignment, size)
    // CRITICAL RULE: 'size' MUST be an integral multiple of 'alignment'
    size_t align = 64;
    size_t size = 256; // 256 is exactly 4 times 64

    void *ptr = aligned_alloc(align, size);

    if (ptr != NULL) {
        printf("\nDynamically allocated memory address: %p\n", ptr);
        
        // Verify the mathematical alignment by casting to an integer type
        if (((uintptr_t)ptr % align) == 0) {
            printf("Success: The pointer is perfectly aligned to a %zu-byte boundary!\n", align);
        }
        
        // Memory allocated with aligned_alloc is freed normally with free()
        free(ptr);
    } else {
        printf("Memory allocation failed.\n");
    }

    return 0;
}
```

- aligned_alloc is implemented by the standard memory allocator (ptmalloc, jemalloc, or tcmalloc)

### Kernel Internal Alignment

```c
#define __aligned(x) __attribute__((__aligned__(x)))

// Example usage in the kernel:
struct network_data {
    int packet_count;
    char buffer[256] __aligned(64); 
};
```

- __attribute__((__aligned__(x))) is a compiler directive
    - not standard c
    - only works on compilers that support GNU syntax (e.g. GCC, Clang)

### Sad Sad Macros

```c
#if defined(__GNUC__) || defined(__clang__)
    #define MY_ALIGN(x) __attribute__((aligned(x)))
#elif defined(_MSC_VER) || __STDC_VERSION__ >= 201112L
    #define MY_ALIGN(x) _Alignas(x)
#else
    #define MY_ALIGN(x) // Fallback for old/unknown compilers
#endif
```

## _Noreturn / <stdnoreturn.h>

Not for void. But for function that would exit in the middle or exec or somethiing equivalent.

- **Dead Code Elimination:** It knows that any code written immediately after the function call is unreachable and can be removed from the binary.
- **Suppressing Warnings:** If a function is supposed to return an `int` but ends by calling a `_Noreturn` function, the compiler won't complain about a "missing return statement."
- **Stack Optimization:** The compiler doesn't need to save the return address or preserve certain registers because it knows the "back button" will never be pressed.

### Example

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdnoreturn.h> // Defines 'noreturn' as '_Noreturn'

// This function will either exit the program or loop forever.
// It never hands control back to main().
noreturn void stop_everything(const char *msg) {
    fprintf(stderr, "Fatal: %s\n", msg);
    exit(1); 
}

int main(void) {
    printf("Initializing system...\n");

    int critical_error = 1;

    if (critical_error) {
        stop_everything("Hardware failure detected.");
        
        // The compiler knows this part of the code is "dead."
        // Most compilers will give you a warning: "code will never be executed"
        printf("This line will never, ever run.\n");
    }

    return 0;
}
```

### Common Use Cases

- **Exit Wrappers:** Functions that call `exit()`, `abort()`, or `quick_exit()`.
- **Infinite Loops:** In embedded systems, the `main` function or the "idle task" often never returns.
- **Long Jumps:** Functions that use `longjmp()` to jump to a different point in the program's execution without returning through the normal stack.

### C23 - bracket syntax

```c
#include <stdio.h>
#include <stdlib.h>

// C23 Style: The attribute is placed before the function declaration.
// It clearly signals to the compiler: "This execution path ends here."
[[noreturn]] void emergency_shutdown(const char *reason) {
    printf("SHUTDOWN: %s\n", reason);
    
    // In a kernel or embedded system, this might be an infinite loop
    // or a call to a hardware reset.
    exit(EXIT_FAILURE); 
}

int main(void) {
    printf("System heartbeat: OK\n");

    int critical_failure = 1;

    if (critical_failure) {
        emergency_shutdown("Power surge detected.");
        
        // This is formally "unreachable code."
        // Modern compilers will often omit this from the compiled binary entirely.
        printf("Trying to recover..."); 
    }

    return 0;
}
```

## _Generic

Replaces stupid tgmath like generics.

```c
//_Generic ( controlling-expression , association-list )

_Generic((variable),
    type1: outcome1,
    type2: outcome2,
    default: default_outcome
)
```

- much cleaner

### Example

```c
#include <stdio.h>
#include <math.h>
#include <stdlib.h>

// _Generic selects the function name (pointer), and THEN we invoke it with (X)
#define absolute_value(X) _Generic((X), \
    int: abs,                           \
    float: fabsf,                       \
    double: fabs,                       \
    long double: fabsl,                 \
    default: fabs                       \
)(X)

int main(void) {
    int i = -10;
    float f = -3.14f;
    double d = -9.81;

    // The compiler expands absolute_value(d) to:
    // (fabs)(d)
    // Which is perfectly valid and causes no type conflicts in unselected branches!

    printf("Integer: %d\n", absolute_value(i));
    printf("Float: %f\n", absolute_value(f));
    printf("Double: %f\n", absolute_value(d));

    return 0;
}
```

## Multi-threading support

### Core components

- **`<threads.h>`:** The main header. It provides the `thread_local` macro (a cleaner wrapper for `_Thread_local`), thread creation (`thrd_create`), and Mutexes (`mtx_t`).
- **`thread_local`:** A storage-class specifier. If you declare a global or static variable as `thread_local`, **each thread gets its own independent copy** of that variable.
- **`<stdatomic.h>`:** Provides lock-free atomic types (like `atomic_int`). These allow multiple threads to read and write to the same variable safely without the heavy performance cost of locking a mutex.

Threads.h isn’t used often. Pthread in linux and WIN32 API still dominates multi-threading in C.

- _Atomic uses TAS and CAS to do atomic operation without holding mutex
- if _Atomic is set on a lage data it might use mutex internally as a fall back

### Why `_Atomic` is superior to a manual Mutex

- **Optimization:** The compiler can often use "Compare-and-Swap" (CAS) loops which are significantly faster than a kernel-level mutex.
- **Memory Ordering:** C11 atomics allow you to specify **Memory Barriers** (like `memory_order_acquire` or `memory_order_release`). This tells the CPU exactly how to synchronize cache across cores without stopping the world.
- **Correctness:** It's impossible to "forget" to unlock an `_Atomic` variable. The synchronization is tied to the variable itself, not the code logic around it.

### Example

```c
#include <stdio.h>
#include <stdlib.h>
#include <threads.h>   // C11 Threads, Mutexes, and thread_local
#include <stdatomic.h> // C11 Atomics

#define NUM_THREADS 5
#define ITERATIONS 10000

// --- Global Variables ---

// 1. Mutex-protected shared variable
mtx_t shared_mutex;
int shared_counter = 0;

// 2. Atomic lock-free shared variable
atomic_int atomic_counter = 0;

// 3. Thread-local variable (each thread gets its own initialized to 0)
thread_local int local_counter = 0; 

// --- The Thread Function ---
// Must return int and take a void* argument
int worker_thread(void *arg) {
    int thread_id = *(int*)arg;

    for (int i = 0; i < ITERATIONS; i++) {
        // --- Mutex Protected ---
        mtx_lock(&shared_mutex);
        shared_counter++; 
        mtx_unlock(&shared_mutex);

        // --- Atomic Protected ---
        // atomic_counter++ safely increments without a mutex lock
        atomic_counter++; 

        // --- Thread Local ---
        // Completely safe to modify without locks; no other thread can see this.
        local_counter++; 
    }

    printf("Thread %d finished. Its local_counter is: %d\n", thread_id, local_counter);
    return thrd_success;
}

int main(void) {
    thrd_t threads[NUM_THREADS];
    int thread_ids[NUM_THREADS];

    // Initialize the mutex (mtx_plain means a standard, non-recursive mutex)
    if (mtx_init(&shared_mutex, mtx_plain) != thrd_success) {
        fprintf(stderr, "Failed to initialize mutex.\n");
        return 1;
    }

    // Create the threads
    printf("Starting %d threads...\n\n", NUM_THREADS);
    for (int i = 0; i < NUM_THREADS; i++) {
        thread_ids[i] = i + 1;
        if (thrd_create(&threads[i], worker_thread, &thread_ids[i]) != thrd_success) {
            fprintf(stderr, "Failed to create thread %d.\n", i);
            return 1;
        }
    }

    // Wait for all threads to finish (Join them)
    for (int i = 0; i < NUM_THREADS; i++) {
        thrd_join(threads[i], NULL);
    }

    // Clean up
    mtx_destroy(&shared_mutex);

    // Print final results
    printf("\n--- Final Results ---\n");
    printf("Expected total for shared counters: %d\n", NUM_THREADS * ITERATIONS);
    printf("Mutex shared_counter:  %d\n", shared_counter);
    printf("Atomic atomic_counter: %d\n", atomic_counter);

    return 0;
}
```

## Subnormal floating-point numbers

Needed to represent a number smaller than the minimum of double.

- If a computer needs to represent number smaller than 1.17e-38 it would just under flow to 0 and would cause mathematical errors in physics and engineering simulations
- It uses Subnormal Numbers to achieve this
    - Instead of holding 1.xxxx * 2^exponenet, uses 0.xxxx * 2^minimum exponent
    - are called subnormal numbers or denormalized numbers
- It has always been there but before C11, a C programmer had no standard way to know if the computer running the code would do the calculation or round down
- C11 simply added the `FLT_HAS_SUBNORM` macro so your code could ask the compiler.

```c
#include <stdio.h>
#include <float.h>

int main(void) {
    printf("--- Subnormal Support ---\n");
    printf("Does float support subnormals?       %d\n", FLT_HAS_SUBNORM);
    printf("Does double support subnormals?      %d\n", DBL_HAS_SUBNORM);
    
    // The smallest normal float vs the smallest subnormal float
    printf("\nSmallest normal float:   %e\n", FLT_MIN);
    printf("Smallest subnormal float:  %e\n", FLT_TRUE_MIN); // Added in C11!

    printf("\n--- Serialization Digits (Float) ---\n");
    printf("Trustworthy digits (FLT_DIG):        %d\n", FLT_DIG);
    printf("Round-trip digits (FLT_DECIMAL_DIG): %d\n", FLT_DECIMAL_DIG);

    // Demonstration of the Round-Trip problem
    float original = 0.1f;
    
    // If we only print to FLT_DIG (6 digits)...
    printf("\nPrinted with %%..%df: %.*f\n", FLT_DIG, FLT_DIG, original);
    
    // To guarantee another parser rebuilds the EXACT binary representation of 0.1f,
    // we must print using FLT_DECIMAL_DIG (9 digits).
    printf("Printed with %%..%df: %.*f\n", FLT_DECIMAL_DIG, FLT_DECIMAL_DIG, original);

    return 0;
}
```

| **Macro Type** | **Example** | **What it tells you** |
| --- | --- | --- |
| **Trustable Digits** | `FLT_DIG` (6) | *Decimal -> Float -> Decimal*. How many digits you can parse without the math getting fuzzy. |
| **Round-Trip Digits** | `FLT_DECIMAL_DIG` (9) | *Float -> Decimal -> Float*. How many digits you must print to serialize a float perfectly. |
| **Subnormal Minimum** | `FLT_TRUE_MIN` | The absolute smallest non-zero number possible, including denormalized states (C11). |

## Anonymous Unions and Structs Inside Struct

### Pre C11

```c
#include <stdio.h>

// Pre-C11 Style
struct LegacyVector {
    union {
        struct { float x, y, z; } coords; // Named struct
        float array[3];
    } data; // Named union
};

int main(void) {
    struct LegacyVector v;
    
    // Look at this terrible, verbose syntax:
    v.data.coords.x = 1.0f;
    v.data.coords.y = 2.0f;
    v.data.coords.z = 3.0f;

    printf("Legacy X: %f\n", v.data.coords.x);
    printf("Legacy Array[0]: %f\n", v.data.array[0]);

    return 0;
}
```

### C11

```c
#include <stdio.h>

// C11 Style
struct ModernVector {
    union { // <-- Anonymous Union
        struct { float x, y, z; }; // <-- Anonymous Struct
        float array[3];
    }; 
};

int main(void) {
    struct ModernVector v;
    
    // Beautiful, clean access.
    // We are writing to the exact same memory location...
    v.x = 1.0f;
    v.y = 2.0f;
    v.z = 3.0f;

    // ...but we can read it directly as an array without deep nesting!
    for (int i = 0; i < 3; i++) {
        printf("Index %d: %f\n", i, v.array[i]);
    }

    return 0;
}
```

- Just like thread macros, MSVC and GCC had supported anonymous structs and unions as non-standard compiler extensions before C11

## Static_assert

```c
#include <stdio.h>
#include <assert.h> // Provides the static_assert macro

// Guarantee that we are compiling on a 64-bit system where pointers are 8 bytes.
static_assert(sizeof(void *) == 8, "This code requires a 64-bit architecture!");

// Guarantee that an integer is exactly 32 bits (4 bytes).
static_assert(sizeof(int) == 4, "Integers must be exactly 32 bits.");

int main(void) {
    printf("Architecture checks passed! Compiling...\n");
    return 0;
}
```

## Exclusive create-and-open mode for fopen

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    const char *lock_file = "app.lock";

    // Attempt to open the file in exclusive mode.
    // "wx" guarantees that if "app.lock" already exists, this fails safely.
    FILE *fp = fopen(lock_file, "wx");

    if (fp == NULL) {
        fprintf(stderr, "ERROR: Another instance is already running "
                        "(or lock file '%s' exists).\n", lock_file);
        return EXIT_FAILURE;
    }

    printf("Lock file acquired. Running application...\n");

    // Write our Process ID (PID) to the lock file just as a best practice
    fprintf(fp, "LOCKED\n");
    
    // Do the actual application work here...
    
    // Clean up
    fclose(fp);
    
    // Remove the lock file when the program finishes normally
    if (remove(lock_file) == 0) {
        printf("Lock file removed safely.\n");
    } else {
        perror("Failed to remove lock file");
    }

    return EXIT_SUCCESS;
}
```

- Behaves like `O_CREAT|O_EXCL` in POSIX
- Fixes TOCTOU Time-of-check to Time-of-use race condition
- Used heavily in security critical systems
- Still lacks permission control
    - Linux / macOS users use `open()` with `O_EXCL` with permission bits

```c
// POSIX way: Atomic creation AND secure permissions
int fd = open("lock.txt", O_CREAT | O_EXCL | O_WRONLY, S_IRUSR | S_IWUSR);
```
